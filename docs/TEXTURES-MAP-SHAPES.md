# 贴图显示与地图形状

需求：user-2026-10-22-texture-map-shapes。用户原话：“卡面和路线图背景，部分敌人的贴图未生效，地图的形状也要有变化”。本轮代码与文档作者/执行者均为Codex；未调用DeepSeek或图像生成器，原十项PNG未修改。

## 图片显示

源码中卡面、地图纸张、图集敌人共同依赖CSS背景和动态URL变量。此轮将关键画面统一改为显式img：卡牌、路线纸张、敌人图集、房间图集、旅人侧栏与地图场景。图集用固定行列数、图片倍数尺寸与负偏移裁切，外层overflow隐藏。卡牌形状徽标仍独立叠加，位图不参与命中计算。

原卡图5×2，新卡图5×4，敌人4×2，房间3×2。位置按“列×视窗宽、行×视窗高”的负偏移设置，不依赖背景百分比。敌人图集加载完成后才隐藏原角色；失败时仍显示基础敌人。新卡图失败回退原卡图，两者都缺失时保留占位和攻击形状；结算和已打开牌堆中的失败图片也会切换。

页面监听实际图片错误，并预加载清单资源；失败显示页脚入口。地图纸张失败仍显示纸色底、连线和节点，房间失败移除插画。资源状态变化只刷新展示，不推进旅途随机数、不保存或发奖。

地图画布移除自身的行内尺寸包含，按父容器可用宽高明确计算宽度并保持比例；预览使用同样规则。图片位于连线和节点下方，不拦截点击。此处修正源码中自动宽度与尺寸包含叠用的风险；未运行浏览器，不把静态发现说成故障唯一根因，也不宣称经过视觉验证。

独立HTML内嵌全部图片。打包按art.js清单读取，缺文件或留下本地外部引用就停止；只合并文本和资源，不执行游戏。dist版本需保持assets完整；旧页面需刷新加载新代码。

## 变化的地图

新旅途默认routeVersion=3，十二站47节点，四种走向：蜿蜒峡谷、双翼回廊、斜行长桥、收束深井。种子决定走向、宽窄站位置、节点偏移、分叉和汇合，不只是更换图标或类型。

起点三节点、首领一节点，中间十站节点数由[2,3,4,4,5,5,5,5,5,5]打乱，总计43；每站2–5节点。坐标按走向、行宽和偏移生成，保持上下站间距。事件、商店、精英、宝箱、营火在指定站各保证至少一个选项，仍由玩家选择路线。

先让当前节点连接下一站最近节点，再给没有入口的下一站节点补连接，最后按种子增加附近的第二分支。因此每个非起点有入口、非终点有出口；从任一起点都能继续到首领，每个节点能从某个起点到达。可选节点、路径校验和画面连线共用next关系；不引入回环、跨站跳跃或重复奖励。

布局与内容采用独立确定序列，渲染和图片加载不重抽地图。重开旅途可改变形状，恢复同一存档会重建同一地图。

## 存档与审阅范围

JSON仍为版本2。routeVersion=1保留八站图，=2保留固定十二站图的节点、类型、敌人和连接，仅增加种子决定的视觉弯曲。=3才使用新形状和连接，不把旧nodeId套到新布局；身体、牌堆和当前战斗不重置。导入白名单接受三个路线版本，原v1降难度迁移继续有效。

仅审阅源码、清单、引用和差异，并合并离线文件。按用户要求未运行游戏、语法检查、测试、浏览器自动化或试玩。图片显示、窗口适配和路线观感由用户确认。
