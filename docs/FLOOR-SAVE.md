# 第一层与存档（v2）

当前新旅途：12站47节点，四种走向与种子决定的宽窄位置、节点坐标及分叉汇合。中间十站每站2–5节点，最后汇聚到3种首领中的1位。所有节点有通向终点的出口，除起点外都有入口。类型/敌人/事件/商店亦由种子决定。详细30卡牌、19敌人、16遗物、12事件与难度见CONTENT-EXPANSION.md；地图生成细节见TEXTURES-MAP-SHAPES.md。

旅途状态为map（选下站）、node（处理房间）、battle（战斗）、reward（领/跳过卡牌）、lost、cleared。不能在当前节点未完成时跳到另一节点。精英/Boss的金币与遗物在battle→reward/cleared时一次发放，并立即保存；结算重开不会再发。

跨节点保留牌组、金币、遗物、身体损伤和血容量。每场清空格挡/强化，补充1次强化剂（有炼金试管为2）；遗物可能额外给予开局资源。包扎不限次数但每次1能量。完成非Boss节点后，存活部位各修复上限5%（向上取整）、全部止血、血容量+10；失去的部位不能再生。

## 格式

顶层format为ember-corridor，version为2，含savedAt、options及run。为自动发现旧存档，本地键继续使用ember-corridor.save.v1，最近替换前备份使用该键加.backup。

run包含seed、rngState、routeVersion、金币、完整牌组、遗物、已走路径、当前节点/状态、待选卡牌、商店已购ID、宝箱roomRelics及结算lastLoot。routeVersion=3为变化形状的新地图，=2保留固定十二站图（仅增加视觉偏移），=1保留旧八站图。地图按种子和路线版本重建；不把新形状的节点/连接应用到已有routeVersion=1/2的旅途，当前战斗与进度不重置。

身体记录部位ID/HP/流血/缺失及父部位关系、血容量、格挡、强化与强化剂。bandages=3仅是兼容字段，当前治疗从不消耗或检查该字段。

战斗保存24格生命层与护甲、maxHp、力量、意图、回合、能量、打牌数、小数攻击余量、全部四个牌堆UID，以及最近120条转义展示的文本日志。构造恢复时不推进实际随机状态，也不重复赠送开局格挡。战斗、事件奖励和掉落的随机数都随存档保留；商店/训练内容由独立的种子节点序列决定，重复渲染不会重抽。

## v1迁移

先完整校验，再恢复旧图、身体和牌堆。旧战斗敌人按照旧生命分布验证，然后以旧剩余比例换算较低新上限，最多保留旧剩余，从旧格子削层，不让空格复活；力量向下减半，意图改为新版相应敌人。包扎限制解除。

v1若已停在精英胜利或Boss通关结算，补发一次未拥有遗物；原金币不重发。迁移后立即另存v1备份并保存为v2，后续恢复按v2处理，不反复补发。原路线直到旅途结束；新开旅途才进入12站47节点图。

## 校验、导入导出与保存边界

导入JSON不得超过128KiB。校验版本、种子/随机状态、节点路径、房间状态、资源范围、遗物白名单、身体上限/缺失关系、敌人生命及完整牌堆分区；卡牌和部位定义从源码重建，不允许导入对象覆盖实例。日志转义显示，不执行导入文本。完整校验成功才显示预览，确认后替换；失败不改变当前旅途。

每个已完成的游戏动作后保存。敌方回合先同步完整结算、写入结果，再播放反馈，因此重新加载不会跳过已提交的敌人行动。导出是标准JSON，跨浏览器、网址或电脑迁移需导出/导入。本地存储失败时顶部显示失败并允许导出，不能声称保存成功。

浏览器、网址和端口隔离本地存储，文件地址亦可能不同。备份保留最近一份，覆盖之前可先导出。游戏存档不等同于代理修改审计。
