# 第一层、节点与存档

作者与执行者：Codex。需求 `user-2026-10-22-floor-save-responsive`。这里记录公开实施结论，不是DeepSeek自审计。

## 路线与旅途状态

固定第一层为八站十八节点，从下向上走，每站选一个节点。相邻站的节点仅在连线存在时可前往，不能跳站、回头或同时领取两条路的奖励。最后一站汇聚到灰冠门主。

| 站 | 可选节点（从左到右） |
| --- | --- |
| 1 | 战斗、战斗 |
| 2 | 事件、战斗、商店 |
| 3 | 营火、精英、事件 |
| 4 | 战斗、宝箱 |
| 5 | 商店、营火、精英 |
| 6 | 事件、战斗 |
| 7 | 营火、宝箱 |
| 8 | Boss：灰冠门主 |

`map`允许选择下一个可达节点；`node`处理营火、商店等房间；`battle`进行战斗；`reward`等待领取/跳过卡牌；`lost`和`cleared`为旅途终态。当前节点尚未完成时，路线按钮只提供查看或返回结算。获胜金币只在`battle → reward/cleared`时发放一次。

牌组、金币、遗物、身体损伤与血容量跨节点保留。初始60金币和10张牌。进入每场战斗时清空格挡、强化回合与上次命中反馈，补充3次包扎和1次强化剂；使用当前身体能力决定初始能量与抽牌量。

完成非Boss节点时，所有存活部位各恢复其上限4%（向上取整、至少1点）、止血、血容量+8，上限100；强化归零。缺失部位不再生，强化结束后若基础能力已不足，仍会失能。敌人和战斗牌堆在下一次遭遇重新建立。

## 节点内容

- 普通敌人根据所在站数变化名称、生命层和攻击，循环攻击、覆甲、蓄势攻击后力量+1。奖励`24 + 零起始站号×3`金币。
- 精英使用更厚生命层，攻击9/覆甲4格/攻击7后力量+1，奖励45金币。
- Boss拥有独立的厚层生命分布，循环攻击10、覆甲6格、攻击8后力量+2；生命不高于一半时所有攻击额外+3，意图立即显示狂怒与实际伤害。击败后获得100金币并通关。
- 战斗或精英获胜后，从余烬、招架、举盾、洞察、重砸、十字斩、横扫、坚守中给出3张不同卡牌，选1张或跳过。奖励选项只生成一次并随存档保留。
- 事件可选择金币+50，或存活部位各修复25%、止血、血容量+35。
- 营火可选择存活部位各修复40%、止血、血容量+45，或获得一张十字斩。
- 宝箱选择残火之心、淬火刀锋或60金币。已拥有的遗物不能重复领取。两种遗物可以同时生效；残火之心增加躯干6、心脏4上限，并为存活的对应部位恢复新增生命。
- 商店：治疗35金币（存活部位各修复30%、止血、血容量+40），横扫35，坚守35，淬火刀锋65；每项每店限购一次，可以购买多项后离开。

实际战斗、卡牌和身体公式由源码定义，当前是供用户试玩的一层原型，未做运行平衡验证。

## 存档格式与恢复

本地存储键为`ember-corridor.save.v1`，最近一次替换前备份键为其`.backup`。JSON顶层标识为`format: ember-corridor`、`version: 1`，含保存时间、Auto/音效偏好与`run`。

保存内容：

- 种子与当前xorshift32随机状态；下一次洗牌、部位命中和奖励使用同一序列。
- 金币、完整牌组、遗物、已完成路线、当前节点、房间购买记录和待选奖励。
- 全部身体部位生命、缺失/连带关系、出血、血容量、格挡、强化剩余回合和医疗次数。部位定义、命中权重与能力公式从源码重建，不信任导入文件替换这些规则。
- 当前敌人生命层、护甲、力量、意图索引、回合、能量、攻击小数余量、状态，以及手牌/抽牌/弃牌/消耗区的卡牌UID。保存最近120条文字战斗日志。

出牌、医疗、结束回合、节点进入/完成、购买、奖励和偏好更改后保存。敌方回合在同一个同步动作里完整结算，写入结果后才播放延迟反馈，不保存一半的敌方回合。重新载入奖励界面时不会重发金币或重新随机奖励。

恢复显式构造Floor、HeroBody与Battle，再逐字段恢复白名单数据；不使用导入对象批量覆盖实例。校验版本、节点路径、终态、卡牌ID/UID与分区唯一性、敌人生命范围、部位上限/缺失父子关系、资源及随机状态范围。导入文件不大于128KiB，JSON解析或校验失败时保留当前旅途。日志在界面转义显示，不执行导入文本。

导入校验完成后先显示进度与资源，用户确认再替换；重开旅途同样有页面确认。替换前保留最近一份本机备份，菜单可将备份导出、再通过普通导入恢复。若浏览器存储不可用，备份至少保留在当前页面内存，离开页面前应导出。

自动存档绑定当前浏览器与网址。文件地址、不同端口、localhost和127.0.0.1可能分别存储；跨位置迁移使用导出/导入。写入失败会改变顶部状态并提示导出，不宣称保存成功。存档是游戏进度，不等同于代理修改审计，也不具有防作弊签名。

## 窗口布局与验证范围

头部、底部手牌和页脚采用窗口高度分配，战斗区及路线区使用剩余空间，不再依赖1056/1310像素的最小页面高度。健康主面板只保留摘要，详情含人体图、22部位与8项能力。路线完整缩放到主体区域；房间选项和健康详情可内部滚动。窄屏或低高度会压缩/隐藏角色装饰，窄屏手牌较多时横向滑动。

按用户要求未运行游戏、测试、语法检查、浏览器自动化或截图；本轮只审阅源码、引用、差异及提交内容，适配与平衡由用户游玩确认。
